# work-orders — チーム運用（役割分担）の進め方

このフォルダは、チラトラの開発を**ひとりでも"チーム開発の作法"で回す**ための仕組み。
`restoration-reform-research` の work-order 方式を、アプリの機能追加向けに翻訳したもの。

**原則: 各ファイルが自己完結する。スレ（セッション）を立て直しても・別フォルダから開いても・
サブエージェントに渡しても、同じ状態から再開できるように書く。会話履歴ではなくファイルを正とする。**

## 役割（ロール）

| 役割 | 誰が | 何をするか | ファイル |
|---|---|---|---|
| **PM** | メインのスレ（CLAUDE.md を把握している本体） | 範囲・受入基準を決める／WOを発行する／**受入（関所）**を判断する／`CLAUDE.md` と `docs/変更管理表.md` を更新する | （専用ファイルなし＝本体スレ） |
| **実装** | 作業スレ | WOに従って実装し、報告を書いて**止まる**。受入基準の外は触らない | `ROLE-implementer.md` |
| **レビュー** | レビュースレ or `/code-review` スキル | 実装の差分を検査し、指摘を返す | `ROLE-reviewer.md` |

PM・実装・レビューを**別々のスレ**で回すと、役割が混ざらず、各スレのコンテキストも軽くなる。
小さな変更なら本体スレ1本で PM 兼務でもよいが、**受入基準を先に書いてから着手**する点は変えない。

## 流れ

```
PM: WO-nnn を書く（目的・受入基準・触ってよい範囲）
      ↓  別スレに「WO-nnn を読んで作業して」と貼る
実装: WO に従って実装 → WO-nnn-report.md に報告して止まる
      ↓
レビュー: 差分を検査（/code-review か ROLE-reviewer）→ 指摘を report に追記
      ↓
PM: 受入基準を満たすか判定（関所）
      - 満たす → WO の状態を「受入」に。docs/変更管理表.md に記録。CLAUDE.md の現在地を更新
      - 満たさない → 直しを WO に追記、または次の WO
```

## ファイルの決まり

- **WO ファイル**: `WO-<連番>-<短いslug>.md`。`WO-TEMPLATE.md` をコピーして作る。
- **報告ファイル**: `WO-<連番>-report.md`。実装スレが書く。
- **状態**は WO 冒頭に書く: `起票` → `作業中` → `レビュー中` → `受入` / `保留`。
- **「真実の所在」**: 仕様・現在地は `CLAUDE.md`、変更の記録は `docs/変更管理表.md`、不具合は `docs/バグ管理表.md`。
  work-orders は「作業の単位と受入の記録」。重複させず、リンクで繋ぐ。

## スレを始めるときに貼る一文（コピー用）

- 実装スレ: `work-orders/WO-nnn-<slug>.md と work-orders/ROLE-implementer.md を読んで作業し、報告を WO-nnn-report.md に書いて止まってください。`
- レビュースレ: `work-orders/ROLE-reviewer.md を読んで、WO-nnn の差分をレビューしてください。`
