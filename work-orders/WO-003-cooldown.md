- 背景: `docs/構想・ロードマップ.md` 構想2「配布タイミング最適化（門前配布のクールダウン）」。同じ場所で短期間に配布が続くと
  受け取り率が下がるため、「しばらく間隔を空ける場所」と「いつから配れるか」を小学校マスタで確認できるようにする。既存の `visits` だけで実現でき、**DB 変更なし**。

  しきい値の設定画面は **WO-004**。旧仕様（小学校ごと）へのレビュー記録は末尾に残す。

## 目的
- 小学校マスタで、学校ごとに各立ち位置の「前回いつ配ったか」「クールダウン中かどうか」「いつから配れるか」が分かる。
- 非推奨の立ち位置（子どもが通らない、より良い場所が見つかった等）は、クールダウンの対象から外れていることが分かる。

## 仕様

### 用語
- **立ち位置**: 既存の `locations`（配布場所）のうち、小学校が設定されているもの（`school_id` が null でない）。配布実績の有無にかかわらず対象。
  **立ち位置名**は `spot` の前後の空白を除いたもの。空（null・空文字・空白だけ）なら「（立ち位置名なし）」と表示する。
- **数える実績**: 次をすべて満たす配布実績（`visits`）: 未削除（`is_deleted = false`）／配布数 `count` が 1以上、または未記入（null）（Q-7）。
- **新しい順**: `date` が新しい順。同じ日なら `start_time` が遅い順（未記入は後ろ）、それも同じなら `created_at` が新しい順、それも同じなら `id` の降順。
  （`date`・`start_time` までは地図のピンの色を決めるビュー `location_pin_status` と同じ。`created_at`・`id` は同順位をなくすために足したもの。
  ビュー側には同順位の決め方が無いため、同じ日・同じ開始時刻の実績が並ぶまれな場合に限り、本 WO の判定とピンの色が食い違うことがある。ビューの変更は範囲外）
- **最新の配布**: その立ち位置の**未削除**の実績のうち、新しい順で先頭のもの（**配布数0も含む**）。**非推奨かどうかの判定に使う**（地図のピンの色と同じ判定）。
- **最新の実績**: その立ち位置の「数える実績」（配布数0を除く）のうち、新しい順で先頭のもの。**クールダウンの日付の計算に使う**。
- **非推奨の立ち位置**: 最新の配布の評価（`rating`）が `bad`（非推奨）の立ち位置。**クールダウンの対象外**（Q-10・Q-11）。
  地図で赤いピンの立ち位置と一致する。次に配って評価が変われば自動で対象に戻る／外れる。
  （運用: 非推奨は「今後ここでは配らない」ときに付ける。通行止め等で配れなかっただけの日には付けない。Q-11）
- **今日**: 日本時間（Asia/Tokyo）の日付（YYYY-MM-DD）。判定は画面を表示した時点の今日で行う（開いたまま日付をまたいでも、再読み込みまで更新しない）。
- **しきい値 N**: 90日（Q-2）。
- **解禁日**: 最新の実績の `date` + N 日。この日から「配布可」。
- **経過日数**: 今日 − 最新の実績の `date`（暦日の差）。未来日なら負の値。
- **クールダウン中**: 今日 < 解禁日。

### 仕様項目（S-n）
- **S-1**: 小学校マスタの各学校のカードの中、学校の行（名前・ボタン列）の下に、カードの幅いっぱいの欄として立ち位置ごとの状態を出す
  （学校の行のボタン列・並びは変えない）。
  - 欄は**最初は畳んで**おき、見出し「立ち位置（{立ち位置の数}）」をタップすると開く。数は**非推奨を含むすべての立ち位置**の数。もう一度タップで畳む。開閉の状態は保存しない（Q-12）。
  - 開くと、**対象の立ち位置**（非推奨以外）を並び順のとおりに並べる。非推奨の立ち位置が1つ以上あれば、その下に小見出し「**非推奨（対象外）**」を置き、非推奨の立ち位置を並び順のとおりに並べる。
    対象の立ち位置が0（全部非推奨）なら、小見出しと非推奨の立ち位置だけを並べる。
  - 立ち位置が1つも無い学校は、見出しを「**立ち位置なし**」とし、開けないようにする（E-17）。
  - **並び順**: 立ち位置名を `localeCompare(a, b, "ja")` で比べた昇順。名前なしは末尾。同じ名前どうしは `id` の昇順。
  - 各立ち位置の行の表示:
  | 状態 | 表示 |
  |---|---|
  | クールダウン中（最新の実績が過去〜今日） | 立ち位置名／ラベル「**クールダウン中**」／「前回 {日付}（{経過日数}日前）」※今日なら「（今日）」／「**{解禁日} から配布可**」 |
  | クールダウン中（最新の実績が未来） | 立ち位置名／ラベル「**クールダウン中**」／「{日付}（予定）」／「**{解禁日} から配布可**」 |
  | 配布可 | 立ち位置名／ラベル「**配布可**」／「前回 {日付}（{経過日数}日前）」 |
  | 数える実績なし | 立ち位置名／「**配布実績なし**」（ラベルなし） |
  | 非推奨 | 立ち位置名／ラベル「**非推奨（対象外）**」／「前回 {最新の配布の日付}」。最新の配布が未来日なら「{日付}（予定）」（クールダウンの計算はしない） |
  日付の書式は既存の `formatDate`（例 `2026/7/6(月)`）。
- **S-2**: ラベルに**赤系・緑系の色を使わない**（評価の色 `rating-*`、同じ赤の `destructive`、Tailwind の `red-*`・`green-*`・`emerald-*` 等を含む）。
  地図で緑＝良好・赤＝非推奨の意味が定着しており、読み違えないため。「クールダウン中」＝`primary` 系、「配布可」＝`muted` 系。
  「非推奨（対象外）」＝`muted` 系の枠線のみ（赤は使わない。「対象外」であることを文字で伝える）。
  判定: スクショを白黒で見ても、ラベルの文字だけで判別できること。
- **S-3**: 判定は画面や DB から切り離した**純粋な関数**で計算する（置き場所 `src/lib/cooldown.ts`）。
  - (a) 今日を求める関数: 現在時刻（`Date`）を引数で受け取り、日本時間の日付を返す。
  - (b) 立ち位置ごとにまとめる関数: 未削除の実績の一覧（`id`・`location_id`・`date`・`start_time`・`created_at`・`count`・`rating`）を受け取り、
    立ち位置ごとに「最新の配布」（配布数0を含む）と「最新の実績」（配布数0を除く）を求める。
  - (c) 状態を求める関数: 最新の配布・最新の実績（それぞれ無ければ無し）・今日・N を受け取り、状態（クールダウン中／配布可／実績なし／非推奨）・
    経過日数・解禁日・未来日かどうかを返す。非推奨の判定を先に行う（最新の配布の評価が非推奨なら、日付に関係なく非推奨）。
    非推奨のときは、表示する日付＝最新の配布の `date`、未来日かどうか＝その日付で判定、経過日数・解禁日＝無し（計算しない）を返す。
  - (d) 表示の並びを組み立てる関数: 学校ごとの立ち位置と状態を受け取り、S-1 の並び（対象→小見出し→非推奨、各々の並び順、名前なし・同名の扱い）と見出しの数を返す。
  - 日付の加減算・差は実行環境のタイムゾーンに左右されない方法で扱う（ローカル時刻の `new Date(y, m-1, d)` に頼らない）。既存 `format.ts` の `todayISO()` は触らない。
- **S-4**: N（90日）は `src/lib/cooldown.ts` の定数1か所で定義する（WO-004 で設定画面の値に置き換える前提）。
- **S-5**: 今日の算出・まとめ（S-3(b)）・状態計算（S-3(c)）・並びと見出しの数（S-3(d)）はサーバー（`schools/page.tsx`）で行い、`SchoolManager` には学校ごとの並び済み・計算済みの表示データだけを渡す
  （実績の一覧は渡さない。並びをブラウザで計算するとサーバーと端末で `localeCompare` の結果が食い違うおそれがあるため）。
- **S-6**: 既存の小学校マスタの機能（追加・編集・位置・URL・削除）の動きと学校の並び順（名前順）は変えない。
- **S-7**: 実績の全件取得は、1ページ分を取る処理を引数で受け取る取得ループの関数として作り、自動テストで確かめられるようにする。
  並び順は一意な列（`id`）で固定。**次のページの開始位置は「それまでに受け取った件数」**とする（「ページ番号×ページサイズ」にしない。Max rows がページサイズより小さいと行を飛ばすため）。各ページで総件数（`count: 'exact'`）も受け取り、取得した合計が総件数に達したら終わる（1ページの件数とページサイズの比較だけで終わりにしない）。
  返りが0件なのに総件数に達していない、合計が総件数と一致しない、途中で総件数が変わった、途中でエラー、のいずれかは**取得失敗**。
- **S-8**: 取得失敗（実績・立ち位置のどちらか）のときは、学校の一覧と既存機能はそのまま使えるようにし、一覧の上にエラー文「**配布実績を読み込めなかったため、クールダウンを表示できません**」を出す。各学校の立ち位置の欄は**見出しを含めて出さない**（「配布実績なし」と見間違えないため）。

### 前提・不変条件
- **DB 変更なし**（新しいテーブル・ビュー・列を作らない）。RLS 変更なし。
- 不変条件: 論理削除済みの実績は、クールダウンにも非推奨の判定にも使わない。配布数0以下の実績はクールダウンの日付に使わない（非推奨の判定には使う）。
- 不変条件: 小学校が未設定の立ち位置は表示しない。
- データ取得: 取得前に「未削除」で絞り込み（配布数0は非推奨の判定に要るので取得する）、必要な列（`id`・`location_id`・`date`・`start_time`・`created_at`・`count`・`rating`）だけを取る（`select *` を使わない）。
  立ち位置は `locations` から必要な列（`id`・`school_id`・`spot`）を、**S-7 と同じ取得ループの関数**で全件取る（失敗の条件も S-7 と同じ。失敗したら S-8）。学校ごとに問い合わせない。
  既存ビュー `location_pin_status` は使わない（日付の計算に配布数0を除いた「最新の実績」が要り、1つの取得で両方を求めるため）。

### 境界ケース（E-n）
例はすべて N = 90、今日 = 2026-10-12 とする。
- **E-1**: 数える実績が無い立ち位置 → 「配布実績なし」。
- **E-2**: 最新の実績が今日（2026-10-12）・評価良好 → クールダウン中、「前回 …（今日）」、解禁日 2027-01-10。
- **E-3**: 最新の実績 2026-07-14（経過 90日） → 配布可（解禁日 2026-10-12 = 今日）。2026-07-15（経過 89日） → クールダウン中、解禁日 2026-10-13。
- **E-4**: 先頭の実績が論理削除された → 残った実績で「最新の配布」（配布数0を含む。非推奨の判定）と「最新の実績」（配布数0を除く。日付）を求め直して判定する。
  例: 残った先頭が「配布数0・非推奨」なら非推奨（対象外）。未削除の実績が無くなれば E-1。
- **E-5**: 最新の実績が未来（2026-10-20） → クールダウン中、「2026/10/20(火)（予定）」、解禁日 2027-01-18。過去と未来が両方あれば最新＝未来日で判定。
- **E-6**: 日本時間 0:00〜9:00 でも日本時間の日付で数える（UTC 2026-10-11 15:30 ＝ 日本時間 10/12 0:30 → 今日 2026-10-12）。
- **E-7**: 同じ学校の別の立ち位置で配った → その立ち位置だけがクールダウン中になり、他の立ち位置は影響を受けない（Q-1）。
- **E-8**: 最新の実績の評価が非推奨 → 非推奨（対象外）。その前の実績が良好でも、最新が非推奨なら対象外（Q-10）。
- **E-9**: 非推奨だった立ち位置で、配布数1以上（または未記入）で配って良好／普通と評価した → 次に開いたときから対象に戻り、クールダウン中になる。
  配布数0で良好／普通と評価した場合も非推奨ではなくなる（最新の配布の評価で決まる）が、日付は配布数0を除いた最新の実績で計算する（無ければ「配布実績なし」）。
- **E-10**: 最新の配布が配布数0・評価が非推奨でない（通行止めで配れず、評価は普通 等） → 非推奨ではない。日付はそれを除いた最新の実績で判定する。
  最新の配布が配布数0・評価が非推奨 → 非推奨（対象外）（Q-11。地図で赤いピンになるのと同じ）。
- **E-11**: 最新の実績が配布数未記入 → 数える実績として判定する。
- **E-12**: 同じ日に同じ立ち位置で2回配った（評価が違う） → 新しい順で先頭（`start_time` の遅い方、未記入は後ろ、同じなら `created_at` の新しい方、それも同じなら `id` の降順）の評価で判定。
- **E-18**: 非推奨の立ち位置で、最新の配布が今日 → 「非推奨（対象外）」と表示し、クールダウン中にはしない。
- **E-19**: 配布数0の実績しかない立ち位置（評価は非推奨でない） → 「配布実績なし」。
- **E-13**: 月末・年末・うるう年をまたぐ解禁日（2026-11-15 → 2027-02-13、2027-12-01 → 2028-02-29）。
- **E-14**: 実行環境のタイムゾーンが日本以外（UTC、America/Los_Angeles）でも E-2〜E-13 の結果が変わらない。
- **E-15**: 取得ループ: 1ページの返りがページサイズより少なくても総件数に達していなければ次を取りに行く／途中でエラー・0件・総件数の変化は取得失敗／実績0件なら成功で全立ち位置「配布実績なし」。
  偽の1ページ取得処理は「要求された開始位置から、上限より少ない件数だけ返す」ものにして、行を飛ばさず全件取り切れることを確かめる。
- **E-16**: デモ表示モード中 → demo スキーマの実績で同じように判定される（確認のみ）。
- **E-17**: 立ち位置が1つも無い学校 → 見出し「立ち位置なし」、開けない。
- **E-20**: 立ち位置名が空白だけ・同じ名前が2つ → 「（立ち位置名なし）」は末尾、同名は `id` 順で両方表示。
- **E-21**: 非推奨の立ち位置で、最新の配布が未来日（2026-10-20） → 「非推奨（対象外）」「2026/10/20(火)（予定）」。経過日数・解禁日は出さない。

### 非機能
- スマホ（主）: 375px 幅で、立ち位置名・ラベル・日付が省略されずに読める。PC でも同じ。
- 性能: S-5（ブラウザに実績を送らない）と問い合わせ回数（総件数＋ページ数分、学校ごとに問い合わせない）で担保。判定はコードレビュー。
- デモ（スクショの準備）: demo のシード実績は 2026年5〜7月。スクショの前に、**デモ表示モードでアプリから**準備する（シードは変更しない。登録したものは残す）:
  - 「みどり第一小学校」の「**正門前**」（直近の評価は良好）に、今日付け・配布数1以上・評価**良好**で実績を登録する（→クールダウン中。直近と同じ評価なので地図のピンの色は変わらない。Q-9）。
    非推奨の立ち位置（丁字路右側・商店街入口）には登録しない（登録しても非推奨のままでクールダウン中にならないため）。
  - 非推奨の例: demo シードの「丁字路右側」（最新 2026-06-25・配布数10・非推奨）がそのまま使える（準備不要）。
  - 配布実績なしの例: 地図クリックで「ひばりが丘小学校」に立ち位置「裏門」を1つ足す（実績は登録しない。残す）。
- 動作確認・登録・撮影はすべて**デモ表示モード**で行う。

### 範囲外（やらないこと）
- 地図・一覧への表示。しきい値の設定画面（WO-004）。立ち位置のまとまり（WO-002・中止）。
- 並び替え・絞り込み、おすすめ順位付け、通知。
- 乗り換え直後のケース（非推奨にした場所の直後に別の場所で配る）の特別扱い（Q-13: 人が履歴を見て判断）。
- 既存 `format.ts` の修正、登録フォームで未来日を禁止すること、地図のピン色のルール変更。

  直し方の案: (a) 実績があれば count に関係なく数える（現行の文言どおり） (b) count=0 は数えない・null は数える
  (c) count=0 も null も数えない。決まった内容を用語・E-n（例: E-11「最新が count=0」）・検証方針に足す。
