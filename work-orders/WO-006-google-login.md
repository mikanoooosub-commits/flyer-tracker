# WO-006: ログイン画面に「Google でログイン」を追加する
- 作成日: 2026-10-13 / 作成: PM / 状態: **仕様承認**（2026-10-13 関所1 オーナー承認。仕様レビュー3回。実装は Opus を推奨）
- コース: **フル**（認証にかかわるため）
- 画面変更: **あり**（ログイン画面）
- 背景: オーナーはシステムごとにアカウントを用意するのが手間で、Google のアカウントで日々ログインしたい。
  大前提（合意済み）: **アカウントの発行権はこちらが持つ**。Google は日々のログイン手段にすぎず、**未登録の Google アカウントは入れない**。
  WO-005（2026-10-13 受入）で、本番プロジェクトにて次を実地で確認済み:
  - 未登録の Google アカウントは、Supabase の「新規ユーザーのサインアップ無効」**だけで拒否される**（`error_code=signup_disabled`）。
  - 登録済みのメールアドレスの Google アカウントは、**既存のユーザーに自動で紐づく**（別のユーザーは増えない）。
  - デモ表示モード（cookie）は Google への往復をまたいで保たれる。
  - 拒否されたとき、今の画面には何も表示されない（エラーは戻り先 URL の `#` 以降で届く）。
  Google Cloud（プロジェクト `chiratora-auth`・OAuth クライアント `chiratora-web`）と本番 Supabase の Google は設定済み。

## 目的
- ログイン画面から Google のアカウントでログインできる（既存のメール＋パスワード、メールリンクも残る）。
- 未登録の Google アカウントで入ろうとしたとき、理由が画面に表示される。

## 仕様

### 前提の確認（1-0。2026-10-13 オーナーと確認済み）
- 利用者はオーナー1人。登録しているメールアドレスと Google アカウントは同じ。
- 既存のログイン方法（メール＋パスワード、メールリンク）は**残し、Google を足す**。
- 「Google でログイン」は**今のログインフォーム（カード）の下**に置く。
- 未登録で拒否されたときの文言は、既存のメールリンクの文言に**揃える**。
- Google 側の公開状態は**本番公開にする**（誰の Google アカウントでも Google 側は通り、拒否は Supabase だけが行う）。
- もらった具体例: WO-005 の検証で、メインの Gmail は入れ、サブの Gmail は拒否された。

### 用語
- **拒否（未登録）**: 戻り先 URL の `#` 以降に `error_code=signup_disabled` が付いている状態。**`?error=auth` が同時に付いていても拒否（未登録）とする**
  （実際の拒否の URL は `/login?error=auth#error=access_denied&error_code=signup_disabled&…` のように両方を持つ。WO-005 T-1）。
- **ログインの失敗（その他）**: 拒否（未登録）ではなく、`#` 以降に `error=` がある、または `?error=auth` がある状態。
  `?error=auth` は Google だけでなく**メールリンクの失敗（期限切れ等）でも付く**ので、メールリンクの失敗でもこの文が出る（Q-5）。
- 判定の優先順位: ①拒否（未登録）→ ②ログインの失敗（その他）→ ③エラーなし。
- 判定は**キーの有無**で決める（値が空でもキーがあれば「ある」とする）:
  - `#` 以降に `error_code` があり、その値が `signup_disabled` → ①拒否（未登録）
  - それ以外で、`#` 以降に `error` または `error_code` のキーがある（値は問わない。空も含む）→ ②ログインの失敗（その他）
  - それ以外で、`?` 以降に `error` のキーがある（値は問わない。`auth` 以外・空も含む）→ ②ログインの失敗（その他）
  - どれも無い → ③エラーなし

### 仕様項目（S-n）
- **S-1**: ログイン画面のログインフォーム（カード）の**下**、デモ表示モードのチェックボックスの**上**に「**Google でログイン**」ボタンを置く。
  パスワードの画面・メールリンクの入力画面・メールリンクの送信済みの表示の**どれを表示していても出す**。
  ボタンの押せる高さは **44px 以上**（既存の「ログイン」ボタンと同じ高さ）、幅はカードと同じ。ボタンは Google のブランドの決まり（Sign in with Google のガイドライン）に沿った見た目にする
  （Google の「G」のロゴ＋文言。ロゴは公式のものを使い、色や形を変えない。実装スレがガイドラインを確認し、出典を report に書く）。
  ガイドラインと既存のボタンの見た目がぶつかるときは: **ロゴ・ロゴの色と形・文言は Google に従う。高さ・幅・角丸・書体は既存のボタンに合わせる。新しいフォントは足さない。**
  ガイドラインと合わない点は report に書く。
- **S-2**: ボタンを押すと Google のログインへ移る（`supabase.auth.signInWithOAuth({ provider: "google", options: { redirectTo: <今の origin>/auth/confirm } })`）。
  押した後は、移るまでボタンを押せなくし、文言を「Google に移動中…」にする（二重に押させない）。
  次のときはボタンを**元に戻す**（押せないまま固まらないように）:
  - `signInWithOAuth` がエラーを返したとき → ボタンを戻し、「ログインに失敗しました。もう一度お試しください。」を出す（表示する場所と消す契機は S-4 と同じ。Google ボタンのすぐ下）。
  - Google の画面からブラウザの「戻る」でログイン画面に戻ったとき（ページが保存から復元された＝`pageshow` の `persisted`）。
- **S-3**: Google でログインに成功すると、既存の流れ（`/auth/confirm` → 地図の画面 `/`）で入れる。`/auth/confirm`（`route.ts`）は変えない。
- **S-4**: ログイン画面を開いたとき、URL に次があればエラー文を表示する（表示位置は「Google でログイン」ボタンのすぐ下）。
  | 状態 | エラー文 |
  |---|---|
  | 拒否（未登録）`#…error_code=signup_disabled…` | 「**このメールアドレスは登録されていません。管理者に招待を依頼してください。**」（既存のメールリンクと同じ文） |
  | ログインの失敗（その他） | 「**ログインに失敗しました。もう一度お試しください。**」 |
  エラーは `#` 以降で届くため、**ブラウザ側で読む**。読んだら URL から **`#` 以降全部と、クエリの `error` だけ**を消す（ほかのクエリは残す。再読み込みで同じエラーが出続けないように。`history.replaceState`）。
  URL の値は画面にそのまま出さない（決まった文だけを出す）。
  表示したエラー文は、**いずれかのボタン（Google でログイン・ログイン・ログインリンクを送る）を押したとき（入力欄で Enter を押して送信したときも含む）に消す**（別のエラー文と重ならないように）。モードの切り替え（パスワード⇔メールリンク）では消さない。
- **S-5**: URL を読んでエラーを判定する処理は、画面から切り離した**純粋な関数**にする（入力: `location.hash` と `location.search` の文字列／出力: エラーなし・拒否・その他の失敗）。自動テストの対象。
- **S-6**: デモ表示モードは今の仕組み（チェックした時点で cookie を付ける）のまま。デモにチェックして Google でログインすると、デモ表示モードで入る（WO-005 T-4 で確認済み。追加の処理はしない）。
- **S-7**: 既存のログイン（メール＋パスワード、メールリンク、初回の方の案内）の見た目と動きは変えない。メールリンクの送信時の既存のエラー表示も変えない。
  変わるのは1点だけ: メールリンクを開いて失敗し `?error=auth` でログイン画面に戻ったとき、S-4 の「ログインに失敗しました。…」が出るようになる（今は何も出ない。Q-5）。
- **S-8**: Google 側の公開状態の切り替え（テスト中 → 本番公開）は、**本番反映のときにオーナーが Google Cloud で行う**（README 手順10 の中で PM が案内）。
  Google が審査を求めた場合は、その時点でオーナーに上げる（このアプリが求めるのはメールアドレス・プロフィール・openid の基本の範囲だけ）。
  本番公開後に本番の URL で未登録が拒否されることは**確かめない**（Q-6。WO-005 とローカルでの E-1 で足りるとする）。
  WO-005 で予定していた「サブの Gmail を Google のテストユーザーから外す」は、本番公開でテストユーザーの制限がなくなるため**行わない**。

### 前提・不変条件
- **未登録の Google アカウントを拒否するのは、Supabase の「Allow new users to sign up」オフだけ**（本番公開後は Google 側の制限がなくなるため、唯一の守り）。
  **この設定をオンにしない**こと。メンバーを増やすときは、今までどおり管理者が招待する（サインアップを開けない）。CLAUDE.md の「勝手に変えないでほしい方針」に追記する（PM）。
  守りは当面この1つで運用する（Q-7。利用者がオーナー1人のため）。二重の守り（ユーザー作成前の照合など）は作らない。**本番反映のたびに、この設定がオフであることを確かめる**（README 手順10 に追記する。PM）。
- Manual linking（手動で別アカウントを紐づける機能）は**オフのまま**。
- DB 変更なし。RLS 変更なし。`/auth/confirm`（`route.ts`）は変えない。
- 秘密情報（クライアント シークレット）はコードにも文書にも出さない（Supabase の設定にだけある）。
- ローカルでログインを確かめるときは **ポート 3000** で起動する（戻り先の許可が `http://localhost:3000/auth/confirm` だけ。README「ローカルでの確認の注意」）。

### 境界ケース（E-n）
- **E-1**: 未登録の Google アカウント（サブの Gmail）→ ログイン画面に戻り、「このメールアドレスは登録されていません。…」が出る。ユーザーは増えない。
- **E-2**: 登録済みの Gmail → 地図の画面に入れる。別のユーザーは増えない。
- **E-3**: Google の画面でキャンセルした・同意しなかった → 判定は戻ってきた URL で決まる: `#error=` または `?error=` が付いて戻れば「ログインに失敗しました。…」が出ること、何も付かずに戻れば何も出ないこと。どちらだったかを report に記録する。
- **E-4**: エラーが出た状態で再読み込み → エラーは出ない（URL から消えているため）。
- **E-5**: `#` 以降に未知のパラメータ・空・壊れた形 → 例外を出さず、用語の「判定はキーの有無」のとおりに判定する。入力例と期待:
  `#error`・`#error=`・`#error_code=`・`#error_code=foo`・`#error=x&error_code=other` → その他の失敗／`#=&`・`#foo=bar`・`#`（空）→ エラーなし（`?error` も無いとき）／
  `?error=xyz`・`?error=` → その他の失敗／`?next=/x` だけ → エラーなし。
- **E-6**: `?error=auth` だけ（`#` なし）→ その他の失敗。
- **E-7**: 「Google でログイン」を素早く2回押す → 1回だけ移動する。
- **E-8**: デモにチェックして Google でログイン → デモ表示モードで入る。チェックを外して Google でログイン → 本番データで入る。
- **E-9**: Google でログインした後、メール＋パスワードでもログインできる（両方使える）。
- **E-10**: 実際の拒否の URL（`?error=auth` と `#error=access_denied&error_code=signup_disabled&error_description=…` の両方）→ 拒否（未登録）の文が出る（その他の失敗の文ではない）。
- **E-11**: `signInWithOAuth` がエラーを返す → ボタンが元に戻り、「ログインに失敗しました。…」が出る。
- **E-12**: Google の画面からブラウザの「戻る」でログイン画面に戻る → ボタンが押せる状態に戻っている。
- **E-13**: Google の拒否の文が出たまま、パスワードでログインして失敗する → 拒否の文は消え、パスワードのエラー文だけが出る。
- **E-14**: メールリンクの期限切れ等で `?error=auth` だけで戻る → 「ログインに失敗しました。…」が出る（Q-5）。

### 非機能
- スマホ 375px で、ボタンが画面幅に収まり、エラー文が省略されずに読める。ボタンの押せる高さは 44px 以上。PC でも同じ。
- 性能: 影響なし（ボタンを1つ足すだけ）。

### 範囲外（やらないこと）
- 既存のログイン方法の削除・変更。メンバーの招待の仕組みの変更。サインアップを開くこと。
- Google 以外の外部ログイン（Apple・GitHub 等）。One Tap（自動で出るログイン）。
- `/auth/confirm` の変更、エラー内容のサーバーでの記録。
- ログイン後の画面での「Google と紐づいています」等の表示、紐づけの解除。
- **共用の端末での利用**: チラトラからログアウトしても、ブラウザの Google のログイン状態は残るため、同じ端末なら次の人が「Google でログイン」を押すだけでオーナーとして入れる。
  オーナー自身の端末だけで使う前提とし、**共用の端末では Google でログインを使わない**（Q-9）。毎回アカウントを選ばせる設定もしない。
- LINE などのアプリの中のブラウザへの対応（Google がアプリ内のブラウザでのログインを断る。Safari・Chrome で開く前提。メール＋パスワードでは入れる。Q-8）。
- 未登録を拒否する二重の守り（Q-7）。本番公開後の本番 URL での拒否の確認（Q-6）。

- R-4【言い回し】対象: S-4（エラー文を消す契機）・E-13
  何が問題か: 「いずれかのボタン…を**押したとき**に消す」とあるが、パスワード・メールリンクのフォームは入力欄で Enter を押しても送信される（`onSubmit`）。Enter での送信も「押したとき」に含むのかが読み手によって分かれる。
  直し方の案: 「ログイン・ログインリンクを送るは**送信したとき（Enter での送信を含む）**、Google でログインは押したとき」に書き換える。

- R-5【仕様の穴】対象: 前提・不変条件・S-8・受入基準
  何が問題か: 本 WO が前提にしている PM・オーナーの作業が3つあるが、**受入基準にも「やること」にも載っておらず、終わったかを確かめる場所が無い**。
  ①CLAUDE.md「勝手に変えないでほしい方針」への「サインアップをオンにしない」の追記（PM）、②README 手順10 への「本番反映のたびにサインアップがオフであることを確かめる」の追記（PM）、
  ③本番反映時の Google 側の公開状態の切り替え（オーナー。PM が案内）。①②は本番公開後の唯一の守りを支える決まりなので、抜けると守りが文書に残らない。
  直し方の案: 受入基準（または「本番反映のときにすること」の欄）に3つをチェック項目として足し、①②は受入までに、③は本番反映のときに確かめる、と時期を書く。
