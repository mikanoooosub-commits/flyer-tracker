# デザインの決まり（チラトラ）

画面を足す・直すときに従う見た目の決まり。WO-007（2026-10-14）で作成。
方向性は**案A「通学路」**（藍を基調、デモの帯は通学帽の黄、UD 書体）。オーナー決定（WO-007 Q-1・Q-2）。
「なぜそうするか」を添えているので、迷ったら理由に立ち返る。決まりを変えるときは WO を起こし、この文書も直す。

- 参考にした考え方: `jp-business-ui` スキル（日本の小規模事業者向け業務画面の手順。デジタル庁デザインシステム・SmartHR Design System の**考え方を参考にしたもの**）。
  公式のデザインシステムに「準拠」はしていない。公式の文章・色の値は写していない。
- 値の置き場所: `src/app/globals.css`（色・角・影）、`src/app/layout.tsx`（書体）。
- 関連: [デザイン点検（2026-10-14）](./デザイン点検_2026-10-14.md)、[コーディング規約](./コーディング規約.md)

## 1. 使い方の決まり

### 1-1. トークンは2層。画面と部品は「意味の名前」だけを使う
- **素の値**: 色・影の値そのもの（例 `--ai-700: #22428f`）。`globals.css` の「素の値ここから〜ここまで」の間**だけ**に書く。
- **意味の名前**: 用途で付けた名前（例 `--text-body`＝本文の文字、`--danger-text`＝危険の文字）。中身は素の値を指す。
- 画面・部品（`src/**/*.tsx`・`*.ts`）と `globals.css` の他の規則（Leaflet の吹き出し等）は、意味の名前（`var(--…)` か、対応する Tailwind のクラス）だけを使う。
- **理由**: 色を変えるときに意味の層だけ直せば全画面が追従する。値が画面に散らばると、直し漏れと「似ているが違う色」が増える（デザイン点検 No.10）。

### 1-2. 値を直接書かない
画面と部品に次を書かない（例外は 1-4）。
- 色の値: `#…`、`oklch(`、`rgb(`・`rgba(`、`hsl(`、CSS の色名（`white`・`black` など）、Tailwind の色の名前（`amber-500`・`white`・`red-600` など）
- 透明度付きの色の指定: `bg-primary/10`・`ring-ring/50` など。淡い地・押している間の色が要るときは、その役割の意味の名前を使う（足りなければ足す）。
  - **理由**: 透明度付きにすると、重なる地によって色が変わり、測ったコントラスト比が当てにならない。決めた名前を使わずに済んでしまう。
  - 例外: 押せない状態を薄くする `disabled:opacity-50` などの不透明度の指定。
- `globals.css` で Tailwind の既定の色・角・影は消してある（`--color-*: initial` 等）。`bg-white`・`rounded-xl`・`shadow-sm` などは**書いても効かない**。

### 1-3. 色だけに頼らない
- 状態・評価は、色と一緒に**文字かアイコン**で出す（例: 吹き出しの履歴は色の点＋「良好」の文字、削除済みは淡い地＋「削除済み」の文字）。
- **理由**: 色覚の違い・日光の下・白黒の印刷では色が読めない。

### 1-4. 直書きの例外（ここに挙げたものだけ）
| 場所 | 何 | 理由 |
|---|---|---|
| `src/app/login/page.tsx` の「Google でログイン」 | ボタンの地・枠・文字・押している間の色（`#FFFFFF`・`#747775`・`#1F1F1F`・`#F2F2F2`） | Google のブランドの決まりによる |
| `src/components/google-logo.tsx` | G のロゴの4色 | 同上 |
| `src/app/layout.tsx` の `themeColor` | `#f4f6fa`（画面の地 `--surface-page`＝`--sumi-50` と同じ色） | メタタグには CSS 変数を使えない。OKLCH は読めない端末があるため `#rrggbb` で書く。**画面の地を変えたらここも直す** |
| `src/lib/note-color.ts` の読み替えの関数 | DB の値の文字列 `"red"`・`"green"` | 以前の地図メモの色の値を、DB を書き換えずに橙・水色として読み替えるため（WO-007 S-7） |
| 色ではない語 | `whitespace-`・`white-space`、`transparent`・`currentColor`・`inherit` | 色の値ではない |

（参考）地図メモの色の選択肢の値 `yellow`・`purple`・`orange`・`blue`・`cyan` は DB に保存する**値の名前**で、色の値ではない（描く色はトークン `--map-note-*`）。

### 2-3. 色の意味（画面をまたいで固定する）
- **基調（藍）と状態の色に赤と緑は使わない**。赤と緑は地図の評価（緑＝良好・赤＝非推奨）と読み違えるため。
  危険だけは赤系を使い、必ず文字かアイコンと一緒に出す。
- **評価の色（`--rating-*`）は評価の表示（ピン・凡例・吹き出し・評価のバッジ）にだけ使う**。成功の表示や変更履歴の印に流用しない。
- 評価のピンの色の方針は変えない: **緑＝良好・灰＝普通・赤＝非推奨**。値を調整するときも色相は保つ。
- 「履歴なし」のピンは**中抜き**（白い地に灰色の枠。枠は白に対して 4.83:1、地図の上で約 2.8px）。「普通」の灰色の塗りと形で見分ける（WO-007 Q-4）。
- 凡例は地図のピンと同じ形・同じ色の小さなピンで描く。
- 成功の表示は基調の濃い藍と同じ色（「保存しました」等は文字とアイコンで伝える。Q-6）。

メモは丸い印で、ピン（評価）とは形が違う。色相（OKLCH の H）を評価の色から離してある。

| 部品 | 8px | `rounded-control` | `var(--shape-control)` | ボタン・入力欄・セレクト・チップ（メモの色・種別の切替）・小さな枠（メモの枠・立ち位置の一覧・検索の候補）・地図の名前のラベル |
| カード | 12px | `rounded-card` | `var(--shape-card)` | カード・ダイアログ・パネル（セレクトの候補・地図の枠）・帯（配置中の帯・ピンから来たときの帯）・デモの選択欄 |
| 丸 | 丸 | `rounded-full` | `var(--shape-round)` | 状態ラベル（クールダウン中 等）・バッジ・アイコンの丸（ヘッダー・ログインのアイコン、アイコンだけのボタン）・メモの印・色の点 |
- 大きさの名前（`rounded-lg` 等）ではなく、**何の部品か**で段を決める。Tailwind の既定の角のクラスは消してあるので使えない。

## 4. 影（2段）と暗幕
| 名前 | Tailwind | 使う場所 |
|---|---|---|
| `--elevation-card` | `shadow-card` | カード・入力欄・主ボタン |
| `--elevation-overlay` | `shadow-overlay` | ダイアログ・セレクトの候補 |
| `--elevation-map-label` / `--elevation-map-mark` | （CSS のみ） | 地図の名前のラベル・メモの印 |
| `--scrim` | `bg-scrim` | ダイアログの暗幕 |

## 5. 文字

### 5-1. 書体
- **BIZ UDPゴシック**（`next/font/google`、太さ 400・700 の2つだけ読み込む）。予備に日本語の標準書体を並べる:
  `"Hiragino Kaku Gothic ProN", "Hiragino Sans", "Yu Gothic", YuGothic, "Noto Sans JP", Meiryo, sans-serif`。
- **理由**: UD（ユニバーサルデザイン）書体で、数字・濁点・似た形の文字が読み分けやすい。屋外のスマホで読む画面に合う。

### 5-2. 文字の大きさの段階（WO-007 で確定。画面への適用は WO-009）
| 段階 | 大きさ | Tailwind | 使う場所 |
|---|---|---|---|
| 補足・最小 | **14px** | `text-sm` | 補足・注記・表（PC）・下のタブ・バッジ・ラベル。**これより小さくしない** |
| 本文 | **16px** | `text-base` | 本文・入力欄（スマホで入力時に拡大されない大きさ） |
| 見出し（小） | 18px | `text-lg` | 見出しで要るときだけ |
| 見出し | **20px** | `text-xl` | 画面の見出し |
| 見出し（大） | 24px | `text-2xl` | 見出しで要るときだけ |
- 基本は 14・16・20px の3段。18・24px は見出しで要るときだけ足す。**最小は 14px**（`text-xs`〔12px〕・`text-[11px]` は使わない）。
- **理由**: 段階が多いと揃って見えない（点検時は 11〜20px の6種類）。14px 未満は読みにくい。
- 地図の名前のラベル・吹き出し（`globals.css` の 11〜13px）も WO-009 で 14px 以上に寄せる。

### 5-3. 太さの段階（WO-007 で確定。クラスの整理は WO-009）
- **400（通常）と 700（強調）の2段**。`font-bold` だけを強調に使う。`font-medium`（500）・`font-extrabold`（800）は使わない。
- 書体は 400・700 しか読み込まないため、今ある `font-medium` は 400 に、`font-extrabold` は 700 に近い見た目で表示されている（WO-007 で許容。WO-009 でクラスを整理）。
- 数字（枚数・日付・件数）は `tabular-nums`（等幅）にする。

## 6. 押す場所（WO-007 で確定。画面への適用は WO-008）
- **押す範囲は 44px 以上**（高さ・幅とも）。アイコンだけのボタン・チップ・文字だけのボタン・チェックボックスのラベル・ダイアログの「×」も含む。
  見た目を小さく保ちたいときは、余白で押す範囲を広げる。
- フォーカスの輪は、全部の部品で `--focus-ring`（不透明の藍）を使う（色は WO-007 で適用済み。太さ・出方の整理は WO-008）。
- **理由**: 指で押し間違えない大きさ。

## 7. 決めなかったこと・後でやること
- **ダークテーマ: 後で**（WO-007 Q-3）。今は作らない（使っていなかった `.dark` の定義も消した）。やるときに意味の名前の層だけ差し替える。
- Leaflet の既定の見た目（拡大縮小のボタン・吹き出しの地・閉じるボタン・著作権表示）は変えていない。チラトラが自前で装飾しているラベルと吹き出しの規則（`globals.css`）だけトークンを使う。
- 余白の段階（4px 刻み）・部品の決まり・文言の決まりは、WO-008〜011 で足す。

## 8. 確かめ方（直書きの検索）
画面を足したら、次の検索が例外（1-4）以外 0 件であることを確かめる。
```
# 色の値・色の名前（src）
rg -n -e '#[0-9a-fA-F]{3,8}\b' -e 'oklch\(' -e 'rgba?\(' -e 'hsla?\(' -e '\b(white|black)\b' -e '-(white|black)\b' \
   -e '\b(amber|red|green|blue|yellow|gray|slate|zinc|neutral|emerald|orange|purple|sky|cyan|lime|teal|indigo|violet|pink|rose)-[0-9]{2,3}\b' \
   src --glob '*.{ts,tsx}'
# 透明度付きの色
rg -n '\b[a-z:\[\]=-]*(bg|text|border|ring|outline|divide|fill|stroke|accent|shadow|placeholder)-[a-z0-9-]+/[0-9]{1,3}\b' src --glob '*.{ts,tsx}'
# 角・影（3段・2段以外）
rg -n -o 'rounded(-[a-z0-9]+)?\b|shadow-[a-z0-9]+' src --glob '*.tsx' | rg -v 'rounded-(control|card|full)|shadow-(card|overlay)'
# globals.css は「素の値ここから〜ここまで」の外を同じ式で見る
```
`whitespace-` は `\bwhite\b` に当たらない。`white-space`（CSS）と、意味の名前 `--map-note-yellow` などの**名前**は当たるので、目で除く（値ではない）。
